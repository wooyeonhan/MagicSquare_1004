## 3. 권장 읽기 순서 (신규 참여자용)

**처음부터 묶음으로 받는 경우:** **[§2 보고서 목록](#2-보고서-목록-및-역할)**으로 전체 지도를 본 뒤, 아래 순으로 들어가면 된다.

1. **01** — 왜 이 문제를 다루는지, “완성”과 학습 목표의 관계  
2. **02** — 입력·출력·에러 계약과 Entity/Control/Boundary 책임  
3. **04** — Epic·스토리·Gherkin으로 구현·테스트를 쪼개는 기준  
4. **`docs/PRD.md`** — 제품 요구의 **단일 기준선**(Report/05와 본문 동기)  
5. **03** — 코딩·TDD·금지 사항(에디터는 루트 `.cursorrules`를 직접 읽어도 됨)  
6. **05** — PRD 변경 이력·갱신 요약만 빠르게 볼 때  

루트 [`README.md`](../README.md)는 위 문서를 링크하고, **구현 후 실행(venv·pytest)** 안내와 함께 **To-Do**를 제공한다. To-Do는 **Epic-001 → US-001~006 → TASK-000~017** 계층, **TDD 마이크로 스텝(RED/GREEN/REFACTOR)**, **Requirements 추적 매트릭스 예시**까지 포함하므로, `04`의 스토리·`02`의 D-/U- ID와 **1:1로 대응**시키기 좋다.
